# INTERRUPTION CONTROL — protect priority without resisting the Founder

## Intent classes
- `CONTINUATION`: pertains to NOW → answer/work in current scope.
- `SIDE_QUESTION`: short clarification → answer and resume, no queue item necessary.
- `IDEA`: capture + assess, current implementation stays unchanged.
- `NEW_TASK`: record scope and collision risk, normally queue it.
- `FOUNDER_OVERRIDE`: explicit priority change request → present consequences and ask confirmation if destructive/sensitive.
- `SAFETY_ALERT`: immediately assess evidence; contain only with authorized operations; never expose secrets or touch live state without approval.

## Focus switch gate (all required)
1. Is NOW truly closed, blocked, or formally suspended?
2. Are exact branch/worktree and uncommitted/local-only edits known and preserved?
3. Have scope and overlap with existing PRs been assessed?
4. Does the proposed target have confirmed authority and completed prerequisites?
5. Is there an explicit Founder-approved lane switch, or a verified safety blocker requiring escalation?
If any missing, do **not** modify execution branch; present one minimal check.

## Founder retains control
When Founder says «ابدأ حاجة تانية»، never dismiss. State: current progress; unfinished work and switching loss; why new work may be better/worse; two clear choices; request focused approval for irreversible changes only. After actual Founder approval, make documented safe handoff — NEVER secretly refuse.

## Scope creep / debug spiral
Two unrelated new items while NOW is open -> offer a 1-minute batch capture, not two workstreams. Three failed retries without new evidence -> halt trial-and-error, trigger quality RCA. Request to prematurely merge -> route to GitHub rules + quality gates, do not equate green CI with live success.
